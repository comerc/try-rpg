## Проект

Это браузерная 2D RTS в духе раннего Warcraft: Phaser 3 + TypeScript + Vite. Игрок строит базу, добывает золото/дерево, обучает войска, ставит точки высадки/сбора, воюет с простым ИИ и побеждает уничтожением вражеской ратуши.

Основной язык интерфейса и ответов по проекту - русский. Пользователя звать Алекс или Шеф, писать коротко и по делу.

## Команды

- `npm run dev` - локальный Vite-сервер.
- `npm run build` - TypeScript check + production build.
- `npm run smoke` - Playwright smoke-проверка запуска игры.
- `npm run assets:ai-atlases` - подготовка референс-листов и промптов для встроенного Codex image-generator.
- `npm run assets:terrain` - регенерация анимированной земли.
- `npm run assets:units` - нарезка кадров всех юнитов из AI-атласов, включая рыцаря.
- `npm run assets:buildings` - нарезка кадров всех зданий из AI-атласов, включая level2.
- `npm run assets:building-upgrades` - совместимый алиас для нарезки level2-зданий из AI-атласов.
- `npm run assets:knight` - совместимый алиас для нарезки рыцаря из AI-атласов.
- `npm run assets:regen` - подготовка промптов/референсов, затем нарезка уже имеющихся AI-атласов terrain/units/buildings.

Перед финальным ответом по коду обычно запускать минимум `npm run build`; после UI/игровых изменений также `npm run smoke`.

## Архитектура

- `src/config.ts` - размеры мира, типы команд/юнитов/зданий, стоимость, характеристики, апгрейды.
- `src/main.ts` - создание Phaser.Game и общий HTML-shell.
- `src/scenes/BootScene.ts` - preload ассетов и fallback-текстуры, если файлов нет.
- `src/scenes/MainMenuScene.ts`, `GameOverScene.ts` - меню и экран результата.
- `src/scenes/GameScene.ts` - игровая сцена, создание карты, ввод, камера, спавн сущностей, события UI/AI.
- `src/scenes/UIScene.ts` - верхняя/нижняя панель, кнопки команд, миникарта, настройки, прогресс строительства/обучения/апгрейда.
- `src/entities/*` - визуально-игровые объекты: `Unit`, `Building`, `ResourceNode`, общий `Entity`.
- `src/systems/*` - правила и подсистемы: экономика, команды, бой, ИИ, выбор, группы, звук, эффекты, туман войны.
- `src/world/*` - карта и поиск пути.
- `src/assets/*` - манифест ассетов и визуальные размеры.
- `scripts/*` - генераторы PNG-ассетов и smoke-тест.

Phaser-сцены должны оставаться адаптерами ввода/отрисовки. Правила игры держать в `systems`, `entities` и `config.ts`, не расползать их по UI.

## Игровые правила

- `UnitKind`: `peasant`, `footman`, `archer`, `knight`.
- `BuildingKind`: `townhall`, `barracks`, `farm`, `tower`.
- Ратуша обучает крестьян и принимает ресурсы.
- Казармы обучают войска; после апгрейда открывают рыцаря.
- Фермы дают лимит еды; апгрейд увеличивает этот лимит.
- Башня атакует автоматически; апгрейд усиливает урон/дальность.
- Апгрейды зданий описаны в `BUILDING_UPGRADES`, итоговые характеристики считаются через `buildingRuntimeStats`.

Если добавляется новый юнит/здание, обновить как минимум:

- `src/config.ts`
- `src/i18n.ts`
- `src/assets/AssetManifest.ts`
- `src/assets/VisualMetrics.ts`
- нужные места в `Unit.ts`, `Building.ts`, `UIScene.ts`, `AIController.ts`
- генераторы или реальные файлы в `public/assets/generated`

## Ассеты

Рабочие ассеты лежат в `public/assets/generated`. Исходные AI-атласы для генерации лежат в `local-assets/generated/v4`; старые `v2/v3`, контакт-листы и эксперименты держать в `local-assets/cleanup-archive`, а не в активном дереве.

Перед генерацией атласов, анимаций и ассетов всегда читать и соблюдать `local-assets/asset-rules.md2` как обязательный источник правил.

Не удалять и не перегенерировать большие пачки ассетов без причины: в репозитории часто есть незакоммиченные сгенерированные PNG. Если меняешь генератор, запускай только нужный скрипт и проверяй, какие файлы он затронул.

Новые юниты, здания, апгрейды зданий и крупные визуальные варианты генерировать через встроенный Codex `image_gen`, а не через OmniRoute и не процедурными SVG/shape-скриптами. Перед генерацией `scripts/generate-ai-atlases.cjs` собирает референс-листы из текущих ассетов в `local-assets/generated/references` и пишет точные промпты в `local-assets/generated/v4/prompts`; существующие ассеты должны использоваться как визуальный референс для стиля, масштаба, силуэта, камеры и цветов фракций.

Все ассеты создавать с четкой видимой сеткой на исходном атласе или листе кадров, чтобы последующая нарезка, выравнивание и ручная обработка были проще и надежнее.

Для зданий один AI-атлас должен описывать только одно здание одной фракции целиком: строительство, обычное состояние, рабочее/боевое состояние, повреждение, улучшенные состояния, разрушение и руины. Не смешивать в одном атласе несколько зданий или обе фракции. Вражеский вариант того же здания делать отдельным атласом с той же геометрией, камерой, масштабом, pivot point и состояниями; менять только фракционные цвета, гербы, флаги и декоративные знаки.

Кадры здания внутри одного атласа должны быть выровнены по одному pivot point. В idle/working/damaged/upgraded-состояниях постоянные части здания не должны шевелиться между кадрами; для construction/destruction уже появившиеся неизменные части должны оставаться на той же пиксельной сетке. После нарезки обязательно проверять contact sheet на дрожание.

Процедурный код допустим для нормализации, нарезки, удаления chroma-key, выравнивания якорей, плавных эффектов травы/воды и мелкого runtime VFX. Он не должен заменять художественную генерацию ключевых ассетов юнитов/зданий.

Для зданий важны:

- `src/assets/VisualMetrics.ts` - масштаб и вертикальная посадка спрайта.
- `Building.updateBuildingSurface` - выбор кадра, стадии строительства/урона, плавность смены.
- `scripts/generate-ai-atlases.cjs` - подготовка референсов и промптов для AI-атласов зданий, включая base/level2.
- `scripts/generate-building-animations.cjs` - нормализация кадров из AI-атласа; сохранять нижний запас, чтобы ратуши, казармы и фермы не резались снизу.
- `scripts/generate-building-upgrade-assets.cjs` - только алиас на нарезку level2 из AI-атласа; не возвращать процедурные рамки/оверлеи как основной ассет.

Для юнитов важны:

- `UNIT_ANIMATION_FRAME_COUNTS` и `unitAnimationKey` в `AssetManifest.ts`.
- `UNIT_VISUAL_SCALE` в `VisualMetrics.ts`.
- `Unit.updateAnimatedTexture` и визуальные акценты в `Unit.redrawTeamAccent`.
- `scripts/generate-ai-atlases.cjs` - подготовка референсов и промптов для AI-атласов всех юнитов, включая рыцаря.
- `scripts/generate-unit-animations.cjs` - нормализация кадров всех юнитов из AI-атласа.
- `scripts/generate-knight-assets.cjs` - только алиас на нарезку рыцаря из AI-атласа; не делать рыцаря процедурным или перекрашенным пехотинцем.

Для травы и воды предпочтительны плавные процедурные runtime-эффекты поверх тайлов: низкая прозрачность, медленные синусные смещения, без резкого переключения кадров и частого мельтешения.

## UI и ввод

- ЛКМ - выделение.
- ПКМ / Option+ЛКМ - команда.
- При выбранных казармах ПКМ по карте задаёт точку высадки/сбора для новых юнитов.
- `A` - атака-движение, `P` - патруль, `H` - держать позицию, `R` - ремонт, `U` - апгрейд здания.
- `Space` - пауза.
- `Ctrl+1..9` - группы.
- `` ` `` - перейти к свободному работнику.
- `Cmd/Ctrl + колесо` - зум, обычное колесо/тачпад - прокрутка.
- Не рисовать дополнительных рамок вокруг зданий и юнитов; допустима только рамка/маркер выбора.

UI рисуется в `UIScene`, а не DOM. Следить, чтобы кнопки помещались в нижней панели при 1920x1080 и compact-режиме.

## Проверка

После изменений:

1. `npm run build`
2. `npm run smoke`
3. Для визуальных правок - открыть игру через dev-server и проверить реальный экран, особенно нижнюю часть карты, здания, нижнюю UI-панель, маркеры казарм и кнопки здания.

Если smoke или build падают, сначала исправить. Если нельзя запустить проверку, сказать это в финальном ответе явно.
